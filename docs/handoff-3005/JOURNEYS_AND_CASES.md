Counts alone cannot prove values, types, NULLs, multiplicity or order. For each populated grid compare complete small-case API rows and exported cells to persisted expected outputs, including deterministic source ordinals. Observe the actual reader branch, request count, payload size and click-to-usable rendering, not only server duration.

## Performance and proof boundaries

Before changing a reader in S3, choose the relevant frozen small case, fixed resources and browser state, then record request count/size, query/serialization and click-to-usable baseline. Set a finite target for that case before implementation. Investigate the whole path, but change only measured bottlenecks. Do not reuse the heavy fixture's old timings as small-case capacity thresholds. A visual loading observation is not a latency benchmark, and a backend READY seal is not a usable-screen pass.
