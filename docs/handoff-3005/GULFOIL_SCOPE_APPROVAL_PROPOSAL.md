# VectorFLOW: production Full and scoped runs

**Pending human approval — revised architecture assessment, 28 October 2026.** One decision is proposed below. No implementation, migration, runtime validation or deployment has been released by this document. The current fast 8080 installation remains unchanged.

## Critical findings

1. **Full and the scoped path are different orchestration contracts.** Ordinary `csv-day` enters `daily_feed` and `production_daily` with a CSV feed attempt. The registered placement path carries a scope request; `production_daily.execute` explicitly rejects combining these two admissions. Making placement Full and its splits agree could leave ordinary Full different, or tempt an implementation to change Full. Preserve ordinary Full as the regression baseline and separately check the applicable canonical rules. Agreement among new paths is necessary, but insufficient.
2. **The previous proposal allowed too much business change.** The actual v2 opening declares site `GulfOil` with `generic-finalization-active-nms-v1`. That label does not enable GulfOil client processing. Canonical GulfOil Post-BPR and Post-BTR do have substantive effects. The proposal must remove test eligibility restrictions without authorizing their integration by implication.
3. **A forward SQL change is required for normal-name scoped reads.** Static tracing of `mta.guard_scope_read_reference` through migrations 0218 → 0219 → 0224 → 0225 → 0228 → 0230 → 0235 → 0238 shows that the case-folded `vftest_fresh_` predicate survives. It executes before the registered-read attachment branch. Changing Python checks alone cannot admit `vectorflow_mta`. This is a source finding; the installed database function has not been queried during this review.
4. **The draft preflight is incomplete.** `run_csv_scope.ps1` calls `inspect`, stops MTA, then calls `register`. Inspection checks opening/site, ownership, input shape and operation state, but the actual certification/registration checks occur later. Unsupported configuration must be refused before service stop. Source export inclusion also does not prove that the native image contains an admissible operator.
5. **Identity and recovery need end-to-end proof.** Test prefixes appear in database admission, archive declarations and filenames. Prefix and terminal selections can share a run ID while selecting different generations. A crash after native commit but before the local receipt is saved leaves an uncertain operation; treating it as a fresh invocation would replay work.

## One proposed decision

Approve a bounded production-contract extension for **normal provisioned names**, including `vectorflow_mta`, and the actual initialized site. Deliver ordinary **Full**, **Up to BPR → Post BPR**, and **Up to DBM → Post DBM** using the same supported explicit configuration and external dataset, with each independent comparison installation maintaining its own predecessor chain.

**The business-policy choice included in this decision is:** support the existing generic business policy for a configured site, including a site labelled GulfOil, without activating GulfOil client effects. Preserve all existing generic calculations and finalization. The new scope contract explicitly records that client effects are not selected; it must not infer this from a site string, absent metadata or the old test profile. A configuration requesting GulfOil client effects, another unsupported effect or an unqualified report definition is refused before service stop or calculation. Adding client producers, custom reports or new business policies is outside this correction.

This follows the retained human decision `COMPLETE-DAILY-PROFILE-ATTRIBUTION` in `docs/LEGACY_EXCEPTIONS.md`. It does not mean that canonical GulfOil hooks are no-ops. If the intended deployment instead requires those client effects, this generic-policy proposal cannot meet that requirement and must be revised before approval. That is the one material business choice; it is not left to implementation discretion.

Preserve ordinary `csv-day` behavior and admission. Do not reroute it through placement Full, loosen its feed/scope rejection, change engine rules, or adjust expected results to obtain equality. Implement the supported CSV-to-scope adapter within the existing native placement entry and ownership model. Placement Full remains an additional comparison path, not the replacement baseline.

Target manual commands, **not yet released**:

```powershell
# Choose ONE route for a date in an independently initialized installation.
.\vf.ps1 csv-day 2026-04-08

# Alternative route, with its own initialization and predecessor chain:
.\vf.ps1 csv-scope 2026-04-08 -Scope UptoBPR
.\vf.ps1 csv-scope 2026-04-08 -Scope PostBPR

# Alternative route, with its own initialization and predecessor chain:
.\vf.ps1 csv-scope 2026-04-08 -Scope UptoDBM
.\vf.ps1 csv-scope 2026-04-08 -Scope PostDBM
```

Use separate provisioned projects/databases for comparisons, without test-name spoofing or shared mutable lineages. A continuation consumes its own accepted prefix. It does not import another route's results or repeat the prefix. The private `.env` retains normal VectorFLOW names; credentials remain outside Git. Update the existing Stage 5 manual guide when the commands are actually qualified.

## Evidence and semantic ownership

The read-only package `I:/data/vectorflow-synthetic-97097-20261027-v2` has its opening and four daily batches directly under that root. Its opening uses the generic policy above. Its separate `config/scope-validation.json` is still a SUPPLIED-INSTANCE test contract with five test no-ops, eight runtime report definitions and independent downloadable RRR disabled. File validation does not qualify runtime behavior. Do not rename the opening, edit this retained package, or silently reinterpret its test profile as a production profile. A new explicit installation scope configuration must agree with the certified opening and supported report definitions. The operator should derive and validate the registration details; the human should not assemble internal hashes.

The ordinary Full route is `vf.ps1 csv-day` → `process_daily_csv` → `daily_feed.stage/execute` → `production_daily.execute` → `temporal.execute_day`, followed by reporting, selection and serving acknowledgement. `temporal._finish_captured_day` selects ordinary `calculate_day` unless a placement request selects `runtime_report_execution.calculate_full`. The two routes have distinct capture and archive mechanisms. Their observable business results must agree under the same policy; their manifests must retain truthful identities and schemas.

The canonical `VectorFLOWv4.bat` places Post-BPR processing before Post-BPR reports/InputData and the UptoBPR stop. PostBPR continuation passes through Pre-DBM, DBM, Post-DBM and its reports before the UptoDBM stop. PostDBM continues through BTR, Post-BTR reports, generic finalization and site-final processing. Retained GulfOil Pre-DBM, Post-DBM and Final batch files say nothing is to be done. Post-BPR invokes `CalculatedAttributes.sql`; Post-BTR invokes attribute/FGTrendData SQL and `GulfOil_BTRReports.py`. Optional Python modules exist, but source presence is not proof of production integration. The inspected generic finalization validator accepts explicit generic policies; it does not select these client modules by site name.

`execute_day` and its accepted native phase/final owners remain authoritative for typed state. Publication owners bind reports to the original producer cut, phase, action revision and catalogue predecessor. Readers, archives and selections are consumers. They cannot synthesize missing business state, move a report to another cut, replay a hook, or turn unavailable data into an empty success. New configuration must name the supported effect policy and report roster explicitly; the eight-report test roster is not automatically the production roster.

## Limited rollout and recovery

Start on a separately owned fresh normal-name installation under the approved resource plan. Preserve its original input package and freeze each date's inputs before its producing invocation. Stop the rehearsal on a failed required proof and retain the failed operation, receipts and files. Do not retry uncertain native work, reinitialize a date, delete a failed run, or copy another route's closing state.

Before any service stop, preflight must establish supported policy/roster, actual namespace/roles, initialization certificate/source, registration compatibility, package/schema capability, input and predecessor identity, and operation/selection state. Revalidate mutable authority under the existing lock immediately before producing. This reduces deterministic interruptions; it does not promise that infrastructure cannot fail after preflight.

If preparation or serving fails after an accepted calculation, recover only from the exact durable accepted run/phase and its valid publication. A service retry must not calculate, rerun hooks or regenerate an already accepted report. If the prior selected view remains valid under the current data/action ownership, an explicitly verified service-only restoration may use it; otherwise keep the affected new service stopped and diagnose. Never restore, overwrite or roll back business data to make an old selection fit.

Keep forward-compatible schema and retained contracts. Do not assume an older executable can read a newly captured version, and do not reverse migrations after new-contract rows exist. Returning to an older service release is permitted only if that release explicitly admits the actual retained schema and selected data; otherwise use a compatible forward correction. The independent permanent 8080 baseline and recovery-only former stack are untouched throughout this proposal.

## Remaining uncertainty and approval wording

Architecture recommendation: **proceed with this narrower generic-policy extension if approved**. Affected contracts are identified, but not runtime-qualified. Source tracing resolves the inherited SQL predicate and the incomplete pre-stop registration check. It does not prove the new dispatch, installed migration, native image, actual CSV/placement equality, crash recovery or large-data resource fit. Those are the finite proofs above. No new tables, generic hook framework, broad test campaign, client integration or Full rewrite is presumed necessary.

**Approval requested:** implement this single bounded change for verified normal production database/site identities under the existing explicit generic policy, preserving ordinary Full and old contracts; add both split routes, truthful archive naming, exact registration/SQL admission, safe manual orchestration and the focused proofs above. Reject unsupported client effects before service stop/calculation. This approval does not enable GulfOil client processing or deploy to the current 8080 baseline.
