# Routine MTA upgrade qualification

The repository-owned upgrade command has passed the checks below in isolated Docker/PostgreSQL installations. A compatible patch authenticates its image while retaining the original installation certificate, accepted data and producer identities. It adds no database permission for each source commit. Real forward MTA migrations remain privileged maintenance.

## Scope and limits

Qualification covers compatible MTA patches and the supported current persisted formats and production generic profile. The actual upgrade projects contain MTA/PostgreSQL; this is not a new full frontend/auth/MTO or browser acceptance campaign. The standalone optional scoped-batch download was not configured by these normal CSV trials and has no new native-path acceptance claim. Historical TEST-profile adapters remain deliberately restricted. No blanket claim is made for all legacy selectors, customer configurations or business-rule branches.

Affected regression groups passed; known historical baseline failures were retained separately. This is not a claim that the entire repository suite is green. Runtime evidence and retained failures remain outside the shareable source.

Breaking persisted formats, non-atomic/cross-service migrations and recovery after new accepted work still require a designed transition. The initial large qualification establishes this upgrade mechanism; future routine patches require affected regression and populated upgrade/readiness checks, not mandatory initialization or replay of historical business days.
